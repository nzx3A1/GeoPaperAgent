一个**只分析地质类论文的 Agent**，不应该只是“上传 PDF 后聊天”，而应该定位成：

> **面向地质科研的论文证据分析助手**：自动阅读论文中的正文、表格、地质图件和公式，围绕具体地质问题检索证据、提取数据、关联多篇论文，并形成可核验的科研结论。

## 一、最核心的三个功能

### 1. 地质专题检索与证据问答

用户提出一个地质问题，Agent 不只是返回相关段落，而是自动完成：

1. 理解问题中的地质对象；
2. 拆分需要研究的子问题；
3. 搜索相关论文和章节；
4. 提取正文、表格、图件中的证据；
5. 对不同论文的结论进行核验；
6. 返回带论文、页码、图号、表号的答案。

例如用户提问：

> 鄂尔多斯盆地延长组长7段页岩油富集主要受哪些因素控制？

Agent 可以拆成：

* 长7段沉积环境是什么；
* 优质烃源岩分布在哪里；
* 储层岩性和孔隙结构如何；
* TOC、Ro、孔隙度、渗透率范围是多少；
* 裂缝、超压、砂泥岩组合有什么影响；
* 不同学者的观点是否一致。

最终输出不是一段泛化回答，而是：

| 控制因素  | 具体结论          | 证据数据          | 来源      |
| ----- | ------------- | ------------- | ------- |
| 烃源岩条件 | 长7暗色泥岩提供主要油源  | TOC 2.1%～6.5% | 论文A，第8页 |
| 储层条件  | 细砂岩、粉砂岩为主要储集层 | 孔隙度6%～12%     | 论文B，表3  |
| 运移条件  | 源储紧邻有利于短距离运移  | 砂泥岩互层         | 论文C，图7  |

这个功能是整个地质 Agent 最重要的入口。

---

### 2. 地质论文多模态解析

地质论文和普通论文最大的区别，是重要信息经常不在正文里，而在：

* 地层柱状图；
* 沉积相图；
* 古地理图；
* 构造位置图；
* 连井剖面图；
* 测井曲线；
* 地震剖面；
* 储层参数平面图；
* 岩心、薄片和扫描电镜图；
* 地球化学交会图；
* 表格和公式。

因此 Agent 必须能理解“文字之外的证据”。

#### 表格解析

从论文表格中提取：

* 井号；
* 层位；
* 岩性；
* 深度；
* 厚度；
* TOC；
* Ro；
* 孔隙度；
* 渗透率；
* 含油饱和度；
* 地球化学参数。

并转成结构化数据：

```json
{
  "well": "X井",
  "formation": "延长组长7段",
  "lithology": "暗色泥岩",
  "toc": {
    "min": 2.1,
    "max": 6.5,
    "unit": "%"
  },
  "evidence": {
    "paper": "论文A",
    "page": 8,
    "table": "表2"
  }
}
```

#### 地质图件解析

例如分析综合地层柱状图时，可以识别：

* 地层层级；
* 深度范围；
* 岩性组合；
* 沉积相；
* 测井曲线变化；
* 海平面升降；
* 储层位置；
* 烃源岩位置；
* 不同轨道之间的对应关系。

例如形成关系：

```text
延长组
  └─ 长7段
      ├─ 岩性：暗色泥岩
      ├─ 沉积相：半深湖—深湖相
      ├─ 富有机质层段：长73
      └─ 证据：图5，第9页
```

这会让 Agent 真正具备地质专业能力，而不是只做 OCR 和文本问答。

### 3. 多篇论文对比与专题综述

Agent 可以围绕一个地质对象，自动比较几十篇甚至几百篇论文。

例如比较“长7段储层特征”时，可以按照固定维度整理：

* 研究区；
* 研究层位；
* 样品数量；
* 岩石类型；
* 物性参数；
* 成岩作用；
* 孔隙类型；
* 沉积微相；
* 主控因素；
* 研究方法；
* 研究结论。

输出：

| 论文  | 研究区      | 主要储层  |   孔隙度 | 主控因素  | 观点       |
| --- | -------- | ----- | ----: | ----- | -------- |
| 论文A | 陕北地区     | 细砂岩   |  8.2% | 压实和胶结 | 成岩作用主控   |
| 论文B | 陇东地区     | 粉砂岩   | 10.1% | 沉积微相  | 沉积作用主控   |
| 论文C | 鄂尔多斯盆地南部 | 凝灰质砂岩 |  7.5% | 裂缝发育  | 裂缝改善储集能力 |

Agent 还可以进一步识别：

* 多数论文共同认可的结论；
* 存在争议的观点；
* 不同区域的差异；
* 不同研究方法造成的结果差异；
* 尚未解决的问题；
* 研究时间上的观点演变。

这比普通的“论文摘要生成”更有价值。

## 二、可以继续扩展的功能

### 4. 地质实体与关系抽取

从论文中识别：

* 盆地、坳陷、凹陷、构造带；
* 组、段、亚段、地质时代；
* 井、剖面、样品；
* 岩石、矿物、沉积相；
* 储层、烃源岩、盖层；
* 断层、裂缝、圈闭；
* 油藏、气藏、流体；
* TOC、Ro、孔隙度、渗透率等参数。

并建立关系：

```text
鄂尔多斯盆地—包含→伊陕斜坡
延长组—包含→长7段
长7段—发育→暗色泥岩
暗色泥岩—具有参数→TOC 2.1%～6.5%
长7段—形成于→半深湖—深湖环境
X井—钻遇→长7段
```

知识图谱适合作为 Agent 的检索和关联工具，但不是最终产品。最终产品仍应是可验证的分析结论、数据表和研究报告。

### 5. 地质数据自动汇总

Agent 可以把分散在不同论文里的数据整理成统一数据集，例如：

```text
研究区—井号—层位—样品深度—岩性—TOC—Ro—孔隙度—渗透率—来源
```

进一步支持：

* 单位统一；
* 层位名称归一化；
* 井名和地名消歧；
* 区间值拆分；
* 异常值检查；
* 重复样品识别；
* 缺失字段标记；
* CSV、Excel、JSON 导出。

这可以让论文数据直接进入后续统计分析，而不是只停留在阅读层面。

### 6. 论文快速精读

针对单篇论文，Agent 可以生成：

* 论文研究对象；
* 核心科学问题；
* 数据来源；
* 使用方法；
* 主要结论；
* 创新点；
* 关键图表；
* 证据是否充分；
* 研究局限；
* 可复现实验步骤；
* 对当前研究项目的价值。

还可以回答：

> 这篇论文最值得看的三张图是什么？

> 论文结论主要由哪些数据支撑？

> 作者说“裂缝改善储层物性”，具体证据在哪里？

### 7. 观点冲突和证据核验

不同论文可能对同一地质问题给出不同解释。

例如：

```text
论文A：长7段优质储层主要受沉积微相控制
论文B：主要受压实和胶结作用控制
论文C：天然裂缝是形成高产井的关键因素
```

Agent 应分析冲突原因：

* 研究区不同；
* 层位划分标准不同；
* 样品数量不同；
* 测试方法不同；
* 数据尺度不同；
* “优质储层”和“高产储层”定义不同；
* 论文研究的是不同阶段或不同成因。

这样可以避免简单地把多篇论文结论拼接在一起。

### 8. 科研线索和研究空白发现

Agent 可以根据论文库发现：

* 哪些区域研究较多；
* 哪些层位研究不足；
* 哪些参数缺少数据；
* 哪些结论长期存在争议；
* 哪些研究主要依赖定性分析；
* 哪些观点缺少井、样品或实验数据支撑；
* 哪些研究方法可以迁移到当前研究区。

例如输出：

> 现有研究普遍讨论长7段储层物性和成岩作用，但针对不同沉积微相中孔喉结构差异的统一定量研究较少。多数研究采用压汞或扫描电镜，缺少多尺度孔隙联合表征。

这可以辅助选题，但 Agent 应明确标注这是“基于现有论文的推断”，而不是已经被证实的新发现。

### 9. 自动生成专题研究材料

Agent 可以根据论文证据生成：

* 文献综述；
* 研究区地质背景；
* 国内外研究现状；
* 某层系沉积特征总结；
* 储层特征分析；
* 成藏条件分析；
* 主控因素总结；
* 论文阅读报告；
* 开题报告资料；
* PPT提纲；
* 专题数据表。

生成内容中的每个重要结论都应绑定：

```text
论文名称 + 页码 + 章节 + 图号/表号 + 原始证据
```

## 三、这个 Agent 应具备的“智能体能力”

真正的 Agent 与普通 RAG 问答的区别，是它能够自主规划和循环执行任务。

例如用户提出：

> 分析近十年鄂尔多斯盆地长7段页岩油富集规律。

Agent 可以自动执行：

```text
1. 解析任务
   ↓
2. 制定研究维度
   ├─ 地层与沉积背景
   ├─ 烃源岩条件
   ├─ 储层特征
   ├─ 运移与保存条件
   └─ 富集主控因素
   ↓
3. 检索论文
   ↓
4. 筛选高相关论文
   ↓
5. 提取正文、表格和图件证据
   ↓
6. 统一地层、区域和参数名称
   ↓
7. 比较不同论文观点
   ↓
8. 检查证据是否充分
   ↓
9. 补充检索缺失内容
   ↓
10. 生成结论、数据表和证据清单
```

过程中发现“烃源岩数据充分，但保存条件证据不足”，Agent 应主动继续搜索，而不是直接生成不完整结论。

## 四、建议的产品功能模块

可以将系统设计为六个主要模块：

| 模块   | 主要功能                  |
| ---- | --------------------- |
| 论文库  | 上传、分类、去重、元数据管理、全文解析   |
| 地质精读 | 单篇论文总结、方法分析、图表解析、结论核验 |
| 专题研究 | 围绕盆地、层位或地质问题开展多论文分析   |
| 数据抽取 | 提取井、层位、岩性和地质参数，形成数据集  |
| 证据检索 | 按页码、段落、图号、表号定位原始证据    |
| 成果生成 | 生成综述、专题报告、对比表和研究提纲    |

## 五、最适合作为第一版的功能范围

第一版不要做得过于庞大，可以集中完成三个闭环：

### 闭环一：单篇论文精读

```text
上传论文
→ 解析章节、表格和图片
→ 生成结构化摘要
→ 支持证据问答
→ 定位原文页码
```

### 闭环二：多篇论文专题研究

```text
选择论文库
→ 输入地质问题
→ 自动拆分研究维度
→ 跨论文检索
→ 观点对比
→ 生成专题分析
```

### 闭环三：地质数据集构建

```text
选择抽取字段
→ 批量提取论文数据
→ 单位和名称统一
→ 人工审核
→ 导出CSV/Excel
```

这三个闭环已经可以形成一个完整的地质论文 Agent，而不是简单的论文聊天机器人。

最终可以把它定义为：

> **GeoPaper Agent：面向地质论文的多模态证据检索、专题研究与结构化数据抽取智能体。**

它的核心价值不是“帮用户读论文”，而是把大量论文转化为**可查询、可比较、可计算、可追溯的地质研究证据**。
